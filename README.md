## 💬 Prompt 工程案例

### 企业 AI 问答 —— 硬性拒绝优化

**背景**

天基隆 AI 问答平台内测初期，用户询问超出知识库范围的问题时，
LLM 频繁直接回复"我不知道"或"我无法回答这个问题"。
抽样 200 条会话日志后发现，硬性拒绝占比高达 42%，
是用户流失的首要原因。需求方反馈："哪怕给个相关的也行，直接说不知道太劝退了。"

**迭代过程**

| 版本 | 做了什么 | 效果 | 学到什么 |
|------|---------|------|---------|
| V1 | 原始 System Prompt，无兜底逻辑 | 硬性拒绝率 **42%** | 模型默认行为是"诚实但无用" |
| V2 | Prompt 层注入角色指令：禁止直接拒绝 + 先给相关信息再引导追问 | 拒绝率降至 **15%** | 光靠 Prompt 约束不够——模型对"什么叫拒绝"的理解不稳定 |
| V3 | 工程侧加置信度阈值（<0.7）+ 自动切换本地知识库检索结果兜底 | 首轮有效回答率 **87%** | Prompt + 工程兜底 > 纯 Prompt 优化 |

**V1 原始 Prompt（问题版本）**
你是一个企业知识助手，请根据知识库回答用户问题。



**V2 优化 Prompt**
你是天基隆平台的企业知识助手。回答规则：

优先从知识库中查找答案
如果找不到精确匹配，告诉用户"我目前没有找到完全匹配的信息， 但以下内容可能相关："然后列出最接近的 2-3 条
绝对禁止直接说"我不知道"或"我无法回答"—— 即使用户的问题超出范围，也要给出相关引导
